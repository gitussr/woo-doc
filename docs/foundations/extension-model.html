WooCommerce Extension Model

The four ways WooCommerce lets you change its behavior — hooks, filters, template overrides, and blocks — what each one can and cannot do, how they compose, and how to choose between them.

P0 · EssentialAudienceIntermediate → AdvancedStatusDraft · Step 1 foundationApplies toWordPress 7.1 · WooCommerce 11.0.1

WooCommerce is built to be changed without editing it. There are four mechanisms for that, and they are not alternatives to pick from at random — each operates at a different layer, and real customizations often use two or three together. This page is the map of the system; the Development section (planned) documents each mechanism in depth.

The four mechanisms

Actions — change what happens

An action is a point in execution where WooCommerce calls do_action( 'some_hook', $context… ). Your callback runs there for effect; its return value is discarded.

  • Good for: outputting extra markup at a known position, sending a notification, writing a log row, creating related data when an order completes, enqueueing a script on WooCommerce pages.
  • Cannot: change a value WooCommerce already calculated. If the price is wrong, an action fired after pricing cannot fix it.

Representative core actions (all still present in 11.0.1):

ActionPosition
woocommerce_before_add_to_cart_form / woocommerce_after_add_to_cart_buttonAround the single-product add-to-cart form
woocommerce_single_product_summaryThe product summary column (priced callbacks at set priorities: title 5, price 10, add-to-cart 30)
woocommerce_checkout_before_customer_details / woocommerce_review_order_before_paymentClassic checkout regions
woocommerce_checkout_create_orderJust before a new order is saved — set order data here
woocommerce_thankyouThe order-received page, with the order ID
woocommerce_order_status_changedAny order status transition

Filters — change a value

A filter is apply_filters( 'some_filter', $value, $context… ). Your callback receives $value, returns a (possibly modified) version, and WooCommerce uses what you return.

  • Good for: adjusting a price, relabelling a button, adding/removing checkout fields, altering a product query, changing an email recipient, toggling whether a gateway is available.
  • Must: always return a value — returning nothing sets it to null and breaks everything downstream.

✓Recommended extension point

For a value change, a filter is almost always the correct mechanism and the highest-safety one. It survives updates and touches nothing else.

Representative core filters (all still present in 11.0.1):

FilterChanges
woocommerce_product_get_price / woocommerce_product_get_regular_price / woocommerce_product_get_sale_priceThe stored price a WC_Product returns
woocommerce_get_price_htmlThe formatted price HTML shown in the catalog
woocommerce_cart_item_price / woocommerce_cart_item_subtotalThe displayed per-line price in the cart (not the amount charged — that is set via set_price() on woocommerce_before_calculate_totals)
woocommerce_checkout_fieldsThe classic checkout field definitions
woocommerce_available_payment_gatewaysWhich gateways are offered at checkout
woocommerce_email_recipient_<id>The recipient of a given transactional email

Actions vs filters — the test

Decision guide

If you want something to appear or happen

Action. Hook the position, echo or do your thing.

If you want an existing value to be different

Filter. Hook the value, return the new one.

If your action echoes markup to 'fix' a wrong number

Stop — you are patching a symptom. Find the filter on the value.

Template overrides — change classic markup

WooCommerce renders classic storefront fragments from PHP files in its plugins/woocommerce/templates/ directory. Core loads them with wc_get_template() / wc_get_template_part(), which call wc_locate_template() to resolve the path — checking yourtheme/woocommerce/<same-path> first, then falling back to the plugin. Copy a template into that theme folder (minus the templates/ segment) and your copy wins. The resolution can also be filtered via woocommerce_locate_template or wc_get_template.

!Possible, but has maintenance cost

A template override is a maintained fork of one file. Each core template carries an @version docblock; WooCommerce → Status → System Status lists every overridden template whose @version is behind the current core template ("version X is out of date. The core version is Y"). When WooCommerce changes that template, your copy does not get the change and can silently drop new markup, hooks, or accessibility fixes. Use only when no hook or filter reaches what you need.

Template overrides only affect the classic front-end. They do nothing to the Cart and Checkout Blocks — a template override of checkout/*.php has no effect on a store using the Checkout Block.

Blocks — change the React storefront

The Cart and Checkout Blocks render on the client and get their data from the Store API. They are not extended with PHP template hooks. Instead:

Classic (PHP templates + hooks)

Customize with actions, filters, and template overrides. Mature, heavily documented, most tutorials target it.

Blocks (Cart/Checkout Blocks)

Customize with block settings, Slot/Fill, checkout filters, IntegrationInterface, and Store API data. Classic display and process hooks — woocommerce_checkout_fields, woocommerce_review_order_before_payment, woocommerce_checkout_order_processed and the like — do NOT run; the server-side equivalent is woocommerce_store_api_checkout_order_processed and friends.

Choosing a mechanism

Decision guide

If a filter exists for the value you want to change

Use it. Done. Highest safety, zero maintenance.

If you need to add output at a known position

Use the action at that position.

If no hook reaches the markup and the store is classic

Override the template. Record it; re-check on every WooCommerce update.

If the store uses Cart/Checkout Blocks

Use block settings, then Slot/Fill, then the integration interface. Do not reach for PHP template overrides.

If only editing a core file would work

Stop. Re-scope the requirement, request an upstream hook, or build a proper extension around the constraint.
