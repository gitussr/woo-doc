WooCommerce Data Model

The core entities WooCommerce manages — products and variations, orders and order items, customers, coupons — what each one is, how they relate, and which storage each lives in across classic and HPOS.

P0 · EssentialAudienceIntermediate → AdvancedStatusDraft · Step 1 foundationApplies toWordPress 7.1 · WooCommerce 11.0.1

WooCommerce's data model is a commerce domain expressed in WordPress's storage. Some entities are custom post types; some are custom tables; order storage is currently mid-migration between the two. This page is the map.

Read WooCommerce Architecture first if you have not — the CRUD-class-over-data-store pattern is what makes this model workable.

All the product and order classes ultimately extend WC_Data, the base class that provides the getter/setter/save() contract and delegates persistence to a data store.

Products

A product is the most WordPress-shaped entity: a product post plus a lot of meta plus taxonomy terms.

Product types are set by the product_type taxonomy term on the product (public => false, hierarchical => false). The built-in terms are simple, variable, grouped, and external (external / affiliate); each maps to a WC_Product_* subclass. Extensions register more (subscription, bundle, composite, …) by adding a term and filtering the class map (woocommerce_product_class / woocommerce_product_type_query).

✓Recommended extension point

$product = wc_get_product( $id ); then $product->get_price(), ->get_stock_quantity(), ->is_in_stock(). The getters read from the right place (lookup table, meta, or computed) — raw meta reads do not.

Orders and order items

An order is a container; the money and the goods live in its items. Even under classic storage, order items were never post meta — they have always been in dedicated tables.

Classic vs HPOS storage

HPOS ("High-Performance Order Storage") settings offer three states: "WordPress post tables" (legacy), "High-performance order storage", and legacy with "compatibility mode" enabled, which syncs writes to both. HPOS has been the default for new installs since WooCommerce 8.2; pre-8.2 stores stay on post tables until migrated. Code that must work everywhere reads and writes only through wc_get_order() / WC_Order, queries only through wc_get_orders(), and never runs WP_Query or direct SQL against a hard-coded order table. Internally, WC_Data_Store::load( 'order' ) returns OrdersTableDataStore or WC_Order_Data_Store_CPT depending on which tables are authoritative. HPOS gets its own section in a later phase.

Customers

"Customer" is two things wearing one CRUD class:

Decision guide

If the buyer has an account

A WordPress user with role customer (capabilities: read plus WooCommerce's own read_private_shop_orders etc. for their own data), plus user meta for billing/shipping address, plus a row in wp_wc_customer_lookup for Analytics. Order history is every order with their customer_id.

If the buyer checked out as a guest

No user row. The customer exists only as the address copied onto the order, plus a transient WC_Customer built from the session during checkout. Analytics still gets a wp_wc_customer_lookup row, keyed by email with user_id = 0, so guest orders are attributed.

Version-specific · WooCommerce 11.0

11.0 added guest order claiming: a logged-in customer can link past guest-checkout orders (matched by email, with email verification) to their account, after which those orders show in their order history.

Coupons

A coupon is a shop_coupon post whose meta holds the rule. The discount_type is one of percent, fixed_cart, or fixed_product; other meta keys include coupon_amount, individual_use, usage_limit, usage_limit_per_user, limit_usage_to_x_items, date_expires, free_shipping, product_ids / exclude_product_ids, product_categories / exclude_product_categories, minimum_amount, maximum_amount. WC_Coupon reads it; the cart totals pipeline applies it.

How the entities relate

Note what is not a database entity: the cart. It is session data (see Architecture → Sessions). Its full structure and the totals pipeline are documented in the Cart section in a later phase.
