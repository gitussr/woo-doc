Checkout

The checkout subsystem — the WC_Checkout controller, where the field list comes from and how to change it, the validation pipeline, how an order is created from the cart, and how all of this differs between classic and the Checkout Block.

P1 · Core DevelopmentAudienceIntermediate → AdvancedStatusDraft · Step 1 foundationApplies toWordPress 7.1 · WooCommerce 11.0.1

Checkout is where a recalculated cart becomes a persisted order. It is also where the classic and Block front-ends diverge the most — the data and order-creation logic is shared, but field handling and validation hooks are completely different.

The controller

WC()->checkout() returns the WC_Checkout singleton. It owns the field definitions, runs validation, and creates the order.

Where the field list comes from

The classic checkout fields are assembled from country-aware address fields plus account and order fields, then passed through filters:

woocommerce_checkout_fields and the address-field filters do not run under the Checkout Block. For the Block, call woocommerce_register_additional_checkout_field() (after woocommerce_init) with a location of contact (saved to the account), address (rendered in both billing and shipping), or order (saved to the order only), plus id, label, type (text / select / checkbox), and optional sanitize_callback / validate_callback.

Validation

Classic (PHP templates + hooks)

woocommerce_checkout_process (no args — call wc_add_notice( …, 'error' ) to block submission), then woocommerce_after_checkout_validation ( $data, $errors ) where $errors is a WP_Error you can add to.

Blocks (Cart/Checkout Blocks)

Server: the Store API validates against each endpoint's schema; woocommerce_store_api_checkout_update_order_from_request runs during order build. Client: the wc/store/validation data store holds errors. The classic wc_add_notice flow is not used.

Order creation

Where does this come from?
What am I looking at?
A custom value chosen in the cart that needs to end up on the order and in emails.
Where does it come from?
Cart item data → copied to an order line item during create_order() → read back from the order item.
What controls it?
The per-line-item creation hook; the order-item meta.
What can I safely modify?
On woocommerce_checkout_create_order_line_item, call $item->add_meta_data( 'Engraving', $values['wd_engraving'] ). Meta with a visible key shows on the order screen and emails automatically.
What should I avoid?
Storing it as order post meta and hand-rendering it everywhere; storing it only in the session.

Under the Block, the equivalent server hook is woocommerce_store_api_checkout_update_order_from_request, plus the ExtendSchema update callback for data the Block collected.
