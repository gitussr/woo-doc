Orders

The order subsystem — the order statuses and what each means, the status-transition hook family, order items, stock reduction timing, refunds, and order notes.

P1 · Core DevelopmentAudienceIntermediate → AdvancedStatusDraft · Step 1 foundationApplies toWordPress 7.1 · WooCommerce 11.0.1

An order is the durable record of a purchase. Its status drives almost every side effect in WooCommerce — emails, stock, downloads, reports — so the status-transition hooks are the most important surface on this subsystem.

Storage (HPOS vs legacy) is covered in WooCommerce Data Model.

Statuses

Order statuses are stored with a wc- prefix internally and referred to without it in code ($order->get_status() returns processing, not wc-processing).

StatusMeaningTypical trigger
pendingAwaiting paymentOrder just created
on-holdAwaiting payment confirmation / manual reviewOffline gateway (BACS/cheque), or a fraud hold
processingPaid, needs fulfilmentPayment complete for a physical order
completedFulfilled, nothing left to doAdmin marks it, or auto for downloads-only
cancelledCancelled by admin or customerManual, or unpaid-order cleanup
refundedFully refundedA refund covering the whole total
failedPayment failed or was declinedGateway rejection

wc_get_order_statuses() returns exactly these seven (each wc- prefixed internally: wc-pending, wc-processing, wc-on-hold, wc-completed, wc-cancelled, wc-refunded, wc-failed). There is also an internal wc-checkout-draft status for a Checkout-Block order that has not been placed yet — it is registered but excluded from wc_get_order_statuses() and the admin dropdown.

To register a custom status, hook all three: register_post_status() for the status itself, woocommerce_register_shop_order_post_statuses so it works under HPOS, and wc_order_statuses to add it to the admin dropdown. Prefix the slug wc-.

Status transition hooks can fire during checkout, from admin, from the REST API, from webhooks, and from bulk actions. Make the callback idempotent — guard with an order meta flag so re-running a transition does not double-send an email or double-charge a downstream system.

Stock and side effects

Stock reduction is also gated by the store-wide woocommerce_manage_stock option and each product's _manage_stock.

Order items

The goods and money on an order are its items, not order meta:

Item classorder_item_typeCarries
WC_Order_Item_Productline_itemproduct/variation id, qty, subtotal, total, tax
WC_Order_Item_Shippingshippingmethod title, method id, cost, taxes
WC_Order_Item_Feefeename, amount, tax
WC_Order_Item_Couponcouponcode, discount, discount tax
WC_Order_Item_Taxtaxrate id, label, tax total, shipping tax total

Iterate with $order->get_items( 'line_item' ) (or 'fee', 'shipping', …). Each item is a CRUD object with its own get_meta() / add_meta_data().

Refunds

A refund is a negative child order (WC_Order_Refund, post type shop_order_refund in legacy mode):

The full argument set is amount, reason, order_id, refund_id, line_items, refund_payment, restock_items. During the call woocommerce_create_refund fires (adjust the refund before save), then woocommerce_refund_created, woocommerce_order_refunded, and one of woocommerce_order_partially_refunded / woocommerce_order_fully_refunded.

  • A refund covering the full total moves the order to refunded.
  • refund_payment => true only works when the gateway declares supports( 'refunds' ) — otherwise the refund is recorded but the money must be moved manually in the processor.

Order notes

$order->add_order_note( $text, $is_customer_note = false ). Customer notes trigger the "Note to customer" email; private notes are admin-only. System events (payment, status changes, gateway messages) are recorded as notes automatically — the note history is the first place to look when debugging an order.
