AJAX

How WooCommerce does AJAX — the admin-ajax endpoint, WooCommerce's own wc-ajax fast path, nonces and the params objects, the built-in cart/checkout AJAX actions, and how to add your own safely.

P1 · Core DevelopmentAudienceIntermediateStatusDraft · Step 1 foundationApplies toWordPress 7.1 · WooCommerce 11.0.1

WooCommerce uses AJAX heavily on the classic front-end: adding to cart from a loop, updating quantities, applying coupons, refreshing the checkout totals. There are two transports, and knowing which one an action uses tells you where to hook it.

Two transports

The public front-end actions routed through wc-ajax are: get_refreshed_fragments, add_to_cart, remove_from_cart, apply_coupon, remove_coupon, update_shipping_method, get_cart_totals, update_order_review, checkout, get_variation, and get_customer_location. WC_AJAX also registers each of these as wp_ajax_woocommerce_<action> and wp_ajax_nopriv_woocommerce_<action> so they still work over admin-ajax.php.

Nonces and the params objects

Front-end scripts receive their endpoint URLs and nonces from small localized objects that WooCommerce prints:

wc_country_select_params / wc_address_i18n_paramswc-country-select / wc-address-i18ncountry/state data, locale field ordering

WooCommerce passes each nonce in the request's security field and checks it server-side with check_ajax_referer( '<action>', 'security' ). Under the Checkout Block none of these apply — the Store API uses its own Nonce / Cart-Token headers.

For your own handlers, verify with check_ajax_referer( 'your-action', 'security' ) (or wp_verify_nonce()), then a capability check where the action is not purely public.

✕Dangerous — avoid

An AJAX handler with no nonce check and no capability check is a CSRF hole — worse if it writes data or reveals another customer's order. Every custom handler: nonce first, capability second, then the work.

Adding your own front-end AJAX

Use the wc-ajax path instead when the call is high-frequency and does not need the admin environment. It fires one hook for logged-in and guest users alike:

There is no wc_ajax_nopriv_* hook. If you register only wc_ajax_<action>, guests reach it too — so your nonce and capability checks are the only gate.

Cart fragments

The mini-cart / cart-count updates after an AJAX add-to-cart come from the cart fragments system: get_refreshed_fragments returns an array of selector => html, filtered by woocommerce_add_to_cart_fragments, and the wc-cart-fragments script swaps each selector's contents and caches the result in sessionStorage. Details and its performance cost are on the JavaScript page.

Blocks note

The Cart and Checkout Blocks do not use wc-ajax. They use the Store API (/wp-json/wc/store/v1/…) with a cart token. A custom wc_ajax_* handler you wrote for the classic checkout will not run under the Block.
