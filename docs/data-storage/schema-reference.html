Data & Storage

Schema Reference

Every WooCommerce-defined database table and its columns — order storage, order items, catalog and customer lookup tables, tax and shipping config, sessions and security, and operational tables.

P4 · ReferenceAudienceAdvancedStatusDraft · Step 1 foundationApplies toWooCommerce 11.0.1

All tables below are prefixed with the WordPress table prefix (wp_ by default) and defined in WC_Install::get_schema(), except the HPOS order tables, defined by the orders data store. This is a lookup page — read Database first for how these tables relate, and HPOS for the order tables specifically.

Read and write through the CRUD layer (wc_get_product(), wc_get_order(), …). This page is for understanding what a query returns and for read-only reporting SQL — not a green light to write to these tables directly.

Orders (HPOS)

wc_orders

The order record.

id, status, type, currency, tax_amount, total_amount, customer_id, billing_email, date_created_gmt, date_updated_gmt, parent_order_id, payment_method, payment_method_title, ip_address, transaction_id, user_agent, customer_note

type distinguishes an order (shop_order) from a refund (shop_order_refund); a refund's parent_order_id points back to the order it refunds.

wc_order_addresses

One row per address on an order.

id, order_id, address_type, first_name, last_name, company, address_1, address_2, city, state, postcode, country, email, phone

address_type is billing or shipping — an order has up to two rows here.

wc_order_operational_data

Internal state not exposed as a primary order field.

id, order_id, created_via, woocommerce_version, prices_include_tax, coupon_usages_are_counted, download_permission_granted, cart_hash, new_order_email_sent, order_key, order_stock_reduced, date_paid_gmt, date_completed_gmt, shipping_tax_amount, shipping_total_amount, discount_tax_amount, discount_total_amount, recorded_sales

wc_orders_meta

id, order_id, meta_key, meta_value — the HPOS equivalent of post meta, for data not promoted to a real column (mostly extensions' own data).

Order line items

Unchanged by HPOS — the same tables serve both legacy and HPOS orders.

woocommerce_order_items

order_item_id, order_item_name, order_item_type, order_id

order_item_type is one of line_item (product), fee, shipping, coupon, tax.

woocommerce_order_itemmeta

meta_id, order_item_id, meta_key, meta_value — per-line detail: product/ variation id, quantity, subtotal/total, tax breakdown, chosen variation attributes.

Catalog and customer lookup tables

Denormalized, indexed copies kept in sync by WooCommerce — never the source of truth. See Database → why the lookup tables exist.

wc_product_meta_lookup

product_id, sku, global_unique_id, virtual, downloadable, min_price, max_price, onsale, stock_quantity, stock_status, rating_count, average_rating, total_sales, tax_status, tax_class

The catalog's fast path for pricing, stock, and rating queries — added in WooCommerce 3.7.

wc_product_attributes_lookup

product_id, product_or_parent_id, taxonomy, term_id, is_variation_attribute, in_stock — primary key on all four identifying columns. Backs attribute-based filtering (including only showing in-stock variations). Population is feature-gated; a store may have this table created but not yet backfilled.

wc_customer_lookup

customer_id, user_id, username, first_name, last_name, email, date_last_active, date_registered, country, postcode, city, state, billing_phone, shipping_phone

user_id = 0 identifies a guest customer, matched by email — see WooCommerce Data Model → Customers.

Analytics lookup tables

Populated from orders as they are placed, and used by WooCommerce Analytics reports instead of querying orders directly.

wc_order_product_lookuporder_item_id, order_id, product_id, variation_id, customer_id, date_created, product_qty, product_net_revenue, product_gross_revenue, coupon_amount, tax_amount, shipping_amount, shipping_tax_amount

wc_order_coupon_lookuporder_id, coupon_id, date_created, discount_amount

Version-specific · WooCommerce 11.0.1

Table shapes here come from WC_Install::get_schema() and the HPOS column-mapping constants for this release. A few tables are created but populated only once a related feature is active (wc_product_attributes_lookup, wc_rate_limits) — an empty table is not necessarily a bug.
