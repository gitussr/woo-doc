WooCommerce uses AJAX heavily on the classic front-end: adding to cart from a
loop, updating quantities, applying coupons, refreshing the checkout totals.
There are **two** transports, and knowing which one an action uses tells you
where to hook it.

## Two transports

    { name: 'WC AJAX (wc-ajax)', note: 'WooCommerce\'s fast path. Request to /?wc-ajax=<action> (or the WC_AJAX::get_endpoint() URL). do_wc_ajax() fires a single wc_ajax_<action> hook — there is no priv/nopriv split here. It sets no-cache headers and skips wp-admin, so it is lighter for front-end calls.' },
  ]}

The public front-end actions routed through **`wc-ajax`** are:
`get_refreshed_fragments`, `add_to_cart`, `remove_from_cart`,
`apply_coupon`, `remove_coupon`, `update_shipping_method`, `get_cart_totals`,
`update_order_review`, `checkout`, `get_variation`, and
`get_customer_location`. `WC_AJAX` also registers each of these as
`wp_ajax_woocommerce_<action>` and `wp_ajax_nopriv_woocommerce_<action>` so
they still work over `admin-ajax.php`.

## Nonces and the params objects

Front-end scripts receive their endpoint URLs and nonces from small localized
objects that WooCommerce prints:

| Object | Attached to handle | Notable keys |
| --- | --- | --- |
| `woocommerce_params` | `woocommerce` | `ajax_url`, `wc_ajax_url` |
| `wc_add_to_cart_params` | `wc-add-to-cart` | `ajax_url`, `wc_ajax_url`, `cart_url`, `is_cart` |
| `wc_cart_params` | `wc-cart` | `ajax_url`, `wc_ajax_url`, `update_shipping_method_nonce`, `apply_coupon_nonce`, `remove_coupon_nonce` |
| `wc_cart_fragments_params` | `wc-cart-fragments` | `ajax_url`, `wc_ajax_url`, `cart_hash_key`, `fragment_name`, `request_timeout` |
| `wc_checkout_params` | `wc-checkout` | `ajax_url`, `wc_ajax_url`, `update_order_review_nonce`, `apply_coupon_nonce`, `remove_coupon_nonce`, `checkout_url`, `option_guest_checkout` |
| `wc_country_select_params` / `wc_address_i18n_params` | `wc-country-select` / `wc-address-i18n` | country/state data, locale field ordering |

<Callout type="info">
  WooCommerce passes each nonce in the request's `security` field and checks it
  server-side with `check_ajax_referer( '<action>', 'security' )`. Under the
  Checkout Block none of these apply — the Store API uses its own
  `Nonce` / `Cart-Token` headers.
</Callout>

For your own handlers, verify with `check_ajax_referer( 'your-action', 'security' )`
(or `wp_verify_nonce()`), then a capability check where the action is not
purely public.

<SafetyLevel level="dangerous">
  An AJAX handler with no nonce check and no capability check is a CSRF hole —
  worse if it writes data or reveals another customer's order. Every custom
  handler: nonce first, capability second, then the work.
</SafetyLevel>

## Adding your own front-end AJAX

```php
// 1. Localize an endpoint + nonce onto a script you enqueue.
wp_localize_script( 'wd-frontend', 'wdAjax', array(
    'url'   => admin_url( 'admin-ajax.php' ),
    'nonce' => wp_create_nonce( 'wd_estimate' ),
) );

// 2. Register the handler for both logged-in and guest users.
add_action( 'wp_ajax_wd_estimate',        'wd_estimate' );
add_action( 'wp_ajax_nopriv_wd_estimate', 'wd_estimate' );

function wd_estimate() {
    check_ajax_referer( 'wd_estimate', 'nonce' );
    $qty = absint( $_POST['qty'] ?? 0 );
    wp_send_json_success( array( 'total' => wc_price( $qty * 9.99 ) ) );
}
```

Use the `wc-ajax` path instead when the call is high-frequency and does not
need the admin environment. It fires **one** hook for logged-in and guest
users alike:

```php
add_action( 'wc_ajax_wd_estimate', 'wd_estimate' ); // logged-in and guests
// Endpoint: WC_AJAX::get_endpoint( 'wd_estimate' ) → /?wc-ajax=wd_estimate
```

<Callout type="warn">
  There is no `wc_ajax_nopriv_*` hook. If you register only `wc_ajax_<action>`,
  guests reach it too — so your nonce and capability checks are the only gate.
</Callout>

## Cart fragments

The mini-cart / cart-count updates after an AJAX add-to-cart come from the
**cart fragments** system: `get_refreshed_fragments` returns an array of
`selector => html`, filtered by `woocommerce_add_to_cart_fragments`, and the
`wc-cart-fragments` script swaps each selector's contents and caches the
result in `sessionStorage`. Details and its performance cost are on the
[JavaScript](/docs/development/javascript#cart-fragments) page.

## Blocks note

The Cart and Checkout **Blocks do not use `wc-ajax`.** They use the
[Store API](/docs/development/rest-api#store-api) (`/wp-json/wc/store/v1/…`)
with a cart token. A custom `wc_ajax_*` handler you wrote for the classic
checkout will not run under the Block.
