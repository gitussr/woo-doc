A shortcode is a `[bracketed]` token in post content that WordPress replaces
with rendered output. WooCommerce registers a set of them through the
`WC_Shortcodes` class on `init`. Two groups matter for different reasons.

## Page shortcodes

The classic Cart, Checkout, and My Account pages are **just WordPress pages
containing one shortcode**:

| Shortcode | Renders | Backing method |
| --- | --- | --- |
| `[woocommerce_cart]` | The cart page | `WC_Shortcodes::cart()` |
| `[woocommerce_checkout]` | The checkout page | `WC_Shortcodes::checkout()` |
| `[woocommerce_my_account]` | The account dashboard, orders, addresses | `WC_Shortcodes::my_account()` |
| `[woocommerce_order_tracking]` | The order-status lookup form | `WC_Shortcodes::order_tracking()` |

WooCommerce stores which page holds which shortcode in options
(`woocommerce_cart_page_id`, `woocommerce_checkout_page_id`,
`woocommerce_myaccount_page_id`). Those page IDs — not the shortcode text —
are how core builds cart/checkout URLs and redirects.

<Callout type="warn">
  Removing the shortcode from the page, or deleting the page, breaks checkout
  routing even if another page renders a cart. Repair from **WooCommerce →
  Status → Tools**, the **"Create default WooCommerce pages"** tool (its button
  reads *Create pages*) — it recreates only missing pages and does not
  overwrite existing ones.
</Callout>

## Product-display shortcodes

For putting products into arbitrary content (a landing page, a blog post):

| Shortcode | Output |
| --- | --- |
| `[products]` | A configurable product grid — the modern, unified one (attributes: `ids`, `category`, `tag`, `limit`, `columns`, `orderby`, `on_sale`, `best_selling`, `top_rated`, …) |
| `[product_page id="99"]` | A full single-product layout for one product |
| `[add_to_cart id="99"]` | Price + add-to-cart button for one product |
| `[add_to_cart_url id="99"]` | Just the add-to-cart URL |
| `[product_categories]` / `[product_category]` | Category tiles / a single category's products |
| `[product]`, `[featured_products]`, `[sale_products]`, `[best_selling_products]`, `[top_rated_products]`, `[recent_products]`, `[related_products]`, `[product_attribute]` | Still registered in 11.0.1 — all handled internally by the same `[products]` renderer with preset attributes |
| `[shop_messages]` | WooCommerce notices (for full-site-editing themes) |

The full set is registered in `WC_Shortcodes::init()`. The `[products]` query
can be filtered:

```php
// Exclude out-of-stock products from every [products]-family shortcode.
add_filter( 'woocommerce_shortcode_products_query', function ( $query_args, $atts, $type ) {
    // $type is the loop name: 'products', 'sale_products', 'featured_products', …
    $query_args['meta_query'][] = array(
        'key'   => '_stock_status',
        'value' => 'instock',
    );
    return $query_args;
}, 10, 3 );
```

`apply_filters( 'woocommerce_shortcode_products_query', $query_args, $atts, $type )`
is called from `WC_Shortcode_Products::parse_query_args()`.

## Registering your own

Nothing WooCommerce-specific — use WordPress's `add_shortcode()`. If your
output depends on the cart or customer, make sure the shortcode is not
running in a context where `WC()->cart` is null, and remember shortcode output
is often **cached** with the page.

<SafetyLevel level="risky">
  Shortcodes that render per-visitor data (cart contents, "hello, name") fight
  full-page caching. Either exclude the page from cache or move the dynamic
  part to a [cart fragment](/docs/development/javascript) / Store API call.
</SafetyLevel>
