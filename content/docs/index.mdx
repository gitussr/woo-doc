WooCommerce can feel like a black box. A button appears on a page and you
cannot tell whether it came from a PHP template, a hook, a block, a shortcode,
a script, or an AJAX response. You want to change one number and you are not
sure what else moves when you do.

**WooDoc exists to remove that fog.** It is a reference for developers who
already know WordPress and now need to understand WooCommerce deeply enough to
build, customize, extend, and debug it with confidence.

## What WooDoc is

A developer-first WooCommerce **engineering reference** — not a "how to run
your store" tutorial and not a marketing site.

Its job is to connect the pieces that WooCommerce functionality is spread
across:

## Who it is for

WooDoc is written for **WordPress developers moving into WooCommerce**.

- **Beginner WooCommerce developer** — comfortable with HTML, CSS, PHP,
  WordPress themes and plugins, but disoriented once WooCommerce is involved.
- **Intermediate WordPress developer** — can build WordPress sites, but
  struggles with templates, hooks, the cart, checkout, product data, AJAX,
  orders, payments, shipping, the database, HPOS, and Blocks.
- **Advanced developer** — wants architecture, extension points, internal
  data flow, debugging strategy, performance considerations, and an honest
  account of WooCommerce's limits.

Every page uses **progressive complexity**: the plain-language explanation
first, the precise developer terminology second.

## What problem it solves

WooCommerce functionality is distributed. The same visible element can be
influenced by WordPress, WooCommerce core, a template, a hook, a filter, PHP,
JavaScript, AJAX, a REST endpoint, a block, a database value, an extension, or
a theme customization.

Most documentation and blog posts hand you a snippet to paste. That teaches
you *what to type* but not *why it works*, *where else you could have done it*,
or *what you just put at risk*. WooDoc connects those pieces so you can make
the decision yourself.

## How WooDoc thinks

Two principles run through every page:

<SafetyLevel level="recommended" title="Teach extension points, not hacks">
  WooDoc distinguishes **recommended extension** (official hooks, filters,
  APIs, supported template mechanisms) from **risky customization** (template
  overrides, replacing behavior) and **dangerous customization** (editing core
  files, relying on fragile internals). *Just because you can change it there
  does not mean you should.*
</SafetyLevel>

<SafetyLevel level="risky" title="Be technically honest about limits">
  WooCommerce cannot do everything well. WooDoc explains what it does out of
  the box, what needs customization, what needs an extension, what needs
  external infrastructure, and when a different stack (custom PHP, Laravel,
  a Node service, a dedicated platform) is the better engineering choice.
</SafetyLevel>

## This is Step 1

WooDoc is being built incrementally. This first release establishes the
foundation: the project definition, the information architecture, the content
design system, and the first conceptual chapters. It deliberately does **not**
try to document every hook, template, setting, or database table yet — that is
what later phases are for. See the [Roadmap](/docs/about/roadmap).
