A payment gateway is an adapter between WooCommerce's order and an external
payment processor. WooCommerce defines the interface; the gateway implements
`process_payment()` and, usually, a webhook handler. This page is the shape of
that interface, not a guide to any one processor.

## The gateway interface

A gateway extends `WC_Payment_Gateway` and is registered via the
`woocommerce_payment_gateways` filter.

## The `process_payment()` contract

```php
public function process_payment( $order_id ) {
    $order = wc_get_order( $order_id );

    // …talk to the processor…

    if ( $success ) {
        $order->payment_complete( $transaction_id ); // pending → processing/completed
        WC()->cart->empty_cart();
        return array(
            'result'   => 'success',
            'redirect' => $this->get_return_url( $order ), // the order-received page
        );
    }

    wc_add_notice( __( 'Payment failed.', 'wd' ), 'error' );
    return array( 'result' => 'failure' );
}
```

`process_payment()` returns `array( 'result' => 'success', 'redirect' => $url )`
on success (WooCommerce redirects the browser there) or
`array( 'result' => 'failure' )` on failure (the checkout page re-renders with
any notices you added). `get_return_url( $order )` is the order-received
("thank you") URL. `payment_complete( $transaction_id = '' )` records the
transaction and moves the order forward — see below.

## Redirect vs direct

<DecisionGuide>
  <Choice when="the processor hosts the payment page">
    `process_payment()` returns a `redirect` to the processor. The customer
    pays off-site and is sent back to a return URL. The order is confirmed
    from the **webhook**, not the browser return (the customer may never come
    back).
  </Choice>
  <Choice when="payment is tokenized client-side (e.g. card fields → token)">
    The token is submitted with the order; `process_payment()` charges it
    server-to-server and completes the order inline.
  </Choice>
</DecisionGuide>

## Webhooks / IPN

Asynchronous processor notifications ("this payment succeeded / was disputed /
was refunded") arrive at a WooCommerce-provided URL:

- `WC()->api_request_url( 'my_gateway' )` returns
  `home_url( '/wc-api/my_gateway/' )` (or the `?wc-api=my_gateway` form).
  `WC_API::handle_api_requests()` fires `woocommerce_api_my_gateway` when that
  URL is hit — this predates the REST API and is still the common gateway
  webhook mechanism; a custom `register_rest_route()` endpoint works too.
- The handler must **verify the processor's signature**, look the order up,
  and move it (`$order->payment_complete()`,
  `$order->update_status( 'failed' )`, `$order->add_order_note()`).

<SafetyLevel level="dangerous">
  A webhook endpoint with no signature verification lets anyone mark any order
  paid. Verify the processor's signature on every call, and treat the payload
  as untrusted input.
</SafetyLevel>

## Saved payment methods (tokenization)

| Piece | Role |
| --- | --- |
| `WC_Payment_Token` (abstract) + `WC_Payment_Token_CC` / `WC_Payment_Token_eCheck` | A stored reference to a payment method (`gateway_id`, `token`, `user_id`, `type`, `is_default`; CC adds `last4`, `expiry_month/year`, `card_type`) — never raw card data |
| `WC_Payment_Tokens` | The facade: `get_customer_tokens()`, `get_order_tokens()`, `get()`, `get_customer_default_token()` |
| `$gateway->supports( 'tokenization' )` | Enables the "save method" checkbox and the saved-methods list at checkout |

Tokens live in `wp_woocommerce_payment_tokens` + `wp_woocommerce_payment_tokenmeta`.
The processor holds the sensitive data; WooCommerce stores only its token —
which keeps most stores out of PCI-DSS scope for card data.

## Blocks

The Checkout Block does not call `payment_fields()`. A gateway registers a
**payment method integration** for the Block separately:

- **Client** — a JS config object (`name`, `label`, `content`, `edit`,
  `canMakePayment`, `ariaLabel`, `supports`) passed to `registerPaymentMethod()`
  (or `registerExpressPaymentMethod()` for express buttons) from
  `@woocommerce/blocks-registry`.
- **Server** — a class extending
  `Automattic\WooCommerce\Blocks\Payments\Integrations\AbstractPaymentMethodType`,
  registered on the `woocommerce_blocks_payment_method_type_registration`
  action (inside a `woocommerce_blocks_loaded` callback) via
  `$payment_method_registry->register( new My_Method() )`.
