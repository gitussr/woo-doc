Checkout is where a recalculated [cart](/docs/lifecycle/cart) becomes a
persisted [order](/docs/lifecycle/orders). It is also where the classic and
Block front-ends diverge the most — the data and order-creation logic is
shared, but field handling and validation hooks are completely different.

## The controller

`WC()->checkout()` returns the `WC_Checkout` singleton. It owns the field
definitions, runs validation, and creates the order.

## Where the field list comes from

The classic checkout fields are assembled from country-aware address fields
plus account and order fields, then passed through filters:

<LayerStack
  layers={[
    { name: 'WC_Countries::get_address_fields()', note: 'billing_/shipping_ address fields, ordered and labelled per the country locale' },
    { name: 'woocommerce_default_address_fields', note: 'filter the shared address field definitions (first_name, last_name, company, address_1, …)' },
    { name: 'woocommerce_billing_fields / woocommerce_shipping_fields', note: 'filter each address group' },
    { name: 'woocommerce_checkout_fields', note: 'the top-level filter — billing, shipping, account, order (order_comments). Add/remove/reorder here.' },
  ]}
/>

```php
// Classic checkout: make the phone field optional and add a delivery note.
add_filter( 'woocommerce_checkout_fields', function ( $fields ) {
    $fields['billing']['billing_phone']['required'] = false;
    $fields['order']['wd_delivery_note'] = array(
        'type'     => 'textarea',
        'label'    => __( 'Delivery note', 'wd' ),
        'required' => false,
        'priority' => 120,
    );
    return $fields;
} );
```

<Callout type="warn">
  `woocommerce_checkout_fields` and the address-field filters **do not run
  under the Checkout Block.** For the Block, call
  `woocommerce_register_additional_checkout_field()` (after `woocommerce_init`)
  with a `location` of `contact` (saved to the account), `address` (rendered in
  both billing and shipping), or `order` (saved to the order only), plus
  `id`, `label`, `type` (`text` / `select` / `checkbox`), and optional
  `sanitize_callback` / `validate_callback`.
</Callout>

Under the Block, the equivalent server hook is
`woocommerce_store_api_checkout_update_order_from_request`, plus the
`ExtendSchema` update callback for data the Block collected.

## Classic vs Blocks — summary

| Concern | Classic | Checkout Block |
| --- | --- | --- |
| Render | `checkout/form-checkout.php` + template hooks | React, data from `wc/store/v1` |
| Fields | `woocommerce_checkout_fields` | Blocks additional-fields API / inner blocks |
| Validation | `woocommerce_checkout_process`, notices | Store API schema + `wc/store/validation` |
| Order created | `woocommerce_checkout_order_processed` | `woocommerce_store_api_checkout_order_processed` |
| Custom data in | `$_POST` on the checkout hooks | `ExtendSchema` update callback |

Order-object hooks (`woocommerce_new_order`, `woocommerce_order_status_changed`,
`woocommerce_thankyou`) fire on **both** paths.
